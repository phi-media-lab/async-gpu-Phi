## 1. Panel

### Systems Architect stance

建立新 story `responsive-execution`，归入 `invisible-exec`，依赖已归档完成的 `unified-runtime`。理由：共享 `gpu_protocol::Priority` 已穿过 task admission、waker requeue、hostcall wire metadata 和 host service queue；它是一条 CPU↔GPU execution-boundary contract，而不是单一 executor enhancement。

已完成的基础：

- executor 固定 High/Normal/Low、Low/Normal reservation、8H:4N:1L service、NOTIFIED wake race、atomic lifecycle、MPMC per-cell sequence；
- hostcall wire metadata、稳定三级 host queue、legacy fallback、显式 High reserve；
- obstacle stress 的真实 GPU admission/first-poll/waker/Low liveness/negative/fallback gates。

新增的独立 gate 已用正确 `KERNEL_IO`、先 load 后 listener 在 RTX 4070 上完成 legacy 32/32 trace（1/1 PASS，64 general credits、reserve=0）；它只能作为 route/JIT/kernel smoke，不能单独证明 hostcall priority、reserve 或 cancellation。该快照时仍未闭环的是 canonical `ONLY_TEST=trace`：它错路由到 compute PTX，忽略 `load_ptx` Result，并在 load 前启动 listener；原命令约 192 秒后 SIGSEGV。这是 harness route/error/lifetime 的 P0 缺口，不是 hostcall ABI 失败。后续完成证据来自 host-side error-visible metrics 与 composed/timeout/safety gates，而不是该 legacy counter。

### Language/Type-System stance

PriML 可严格迁移的最小核心是：一个高优先级 context 不得等待较低优先级 typed handle。该快照中的 `gpu-runtime/src/priority.rs` 已朝这个精确方向实现 `PriorityToken<P>`、`MayWaitFor<Target>`、`TypedJoinHandle`、caller-owned `CompletionCell` 和 trace identity；最终 wire ID 为 `(namespace:u32 << 32) | local_sequence:u32`，local 到 `u32::MAX` 返回 `TraceIdExhausted` 而不回绕。compile-pass/fail corpus 已存在。

不能直接宣称已迁移 PriML：

- PriML 支持 partial order、priority polymorphism，以及 2026 工作中的 first-class/dynamic priorities；当前只有封闭的三层 total order。
- 2023 PriML synchronization 对 CV 使用静态 priority/ownership/promote，对 mutex 使用动态 priority ceiling/inheritance；当前 raw channels/locks/condvars 不受 typed token 约束。
- `set_effective_priority()` 仅在下一次 re-enqueue 生效，已 QUEUED task 不迁队；这还不是严格 priority inheritance。
- Typed completion 避免把 recyclable `TaskId` 当 join capability；该 brainstorm 快照时 RawWaker 仍没有 slot generation，后续 generation-tagged authority 与 Phase3 stale-key GPU litmus 已闭合这一缺口。

### GPU Architect stance

当前证据足以建立 dispatch-count contract，不足以建立 wall-clock contract：

- RTX 4070：Low 224/224 后 High accepted；inject 225→first 226→resume 227；223/223 Low 完成；225/225 terminal；450 polls；all gates=1。
- 有界 non-yielding Low：High 在 Low return 后才 poll（1→2→3，约 8.9ms 仅诊断），直接证明无 mid-poll preemption。
- 当前真实 stress 仅单 warp、纯 Low backlog。若混入 Normal，8H:4N:1L 理论允许最多 5 个 lower-priority dispatch；multi-warp cursor fairness 尚无模型或对抗测试。

GPU 特有的不可迁移条件：SIMT convergence、warp-uniform priority、active mask、block residency、memory scope、barrier participation、driver/JIT/PCIe/host syscall。CPU DAG/cost theorem不能在没有这些假设时直接给 GPU response-time bound。

### VectorWare/API stance

Priority 属于 VectorWare 四层模型的 control plane：`std/hostcall + Future + thread lifecycle`。它增强的是 brownfield portability 与跨 CPU/GPU 统一任务语义，不是数据平面峰值性能。

透明 portable SIMD 仍是独立、最大的 VectorWare 缺口；PriML priority/type/cost work 不会生成 uniform/varying type system，也不会把 `core::simd::Simd<T,N>` lowering 到 warp lanes。因此完成 `responsive-execution` 不能被表述为完成 VectorWare 架构。

### Skeptic stance

最危险的错误结论有四个：

1. 把 “High 下一次被 poll” 写成 hard-real-time deadline；
2. 把 fixed 8:4:1 写成 PriML fairly-prompt theorem；
3. 把 typed join 的 compile-fail 写成 raw Future/channel/lock 全程序无 inversion；
4. 用独立 ignored E2E 的 PASS 掩盖 canonical `ONLY_TEST=trace` 仍然存在的 PTX route/error/lifetime 缺陷，或反过来把该 harness 缺陷误判为 hostcall ABI 失败。

## 2. Consensus

1. 新 work 的准确主归属是 `invisible-exec / responsive-execution`；`lang-complete` 与 `codebase-health` 是横向影响，不新增 epic。
2. `priority-executor` 与 `obstacle-stress` 是已完成、真实 GPU 验证的 foundation；不应重做。
3. `priority-hostcall` 的 protocol/runtime/host 实现、CPU tests 与正确 IO 路由的独立 legacy GPU E2E 已完成；canonical trace harness 仍是 **FAIL**，opt-in reserve 的真实 GPU saturation 仍未证明，因此新 feature 保持 active。
4. Typed priority wait 正在进行，只能对通过 typed API 构造的 join dependency 做静态保证；必须保留 escape-hatch 范围说明。
5. 下一批 P0 是 correctness/evidence closure：正确 PTX route、load error propagation、generation-safe waker、typed join runtime/cancellation E2E。
6. Priority guarantee 只覆盖 admission 和 cooperative poll/service boundaries。没有 bounded poll quantum、GPU-specific progress assumptions 和系统级 watchdog 时，禁止任何 hard-real-time 表述。
7. PriML 最有价值的下一步不是照搬编译器，而是先迁移最小 typed dependency relation，再以 GPU 专属反例逐步扩展到 channels/CV/cost model。

## 3. Disagreements

### 是否重开 archived `gpu-executor`？

- Pro：executor 的语义已从单 FIFO 大幅演进，且修复了原 MPMC correctness bug。
- Con：archived story 的四项原始 success criteria 仍然全部成立；新工作跨 executor、hostcall、typed sync 和 safety boundary，重开会错误缩窄范围。
- **Resolution**：不重开；把它作为 `responsive-execution` 的完成依赖和 baseline evidence。

### 是否归入 `lang-complete`？

- Pro：PriML 的主要贡献是 type system，当前也有 typed marker/compile-fail。
- Con：用户价值来自 runtime+host boundary，且 type guarantee 只覆盖 opt-in typed handles，不是 “every Rust feature works”。
- **Resolution**：主归 `invisible-exec`；typed feature 明确记录对 `lang-complete` 的次级贡献。

### 是否以 deadline 作为 story success criterion？

- Pro：用户场景是机器人障碍事件。
- Con：当前 non-yielding 负例已经证明无法给 wall-clock upper bound；host syscall 和 GPU residency 也不可抢占。
- **Resolution**：只要求 freshness/deadline fallback decision 与 fault-injection 可观察，不要求 scheduler 硬 deadline；真实 actuator 与 safety certification 明确 out of scope。

## 4. Resolved

- Shared wire enum：`gpu_protocol::Priority` 是 executor/hostcall 唯一 runtime priority 类型。
- Legacy compatibility：旧 `spawn()`=Normal；旧 HostcallBuffer reserve=0；unknown wire metadata 回退 Normal/task_id=0。
- Executor admission：Low 224、Normal 240、High 256；Low 饱和不耗尽 High slots。
- Cooperative dispatch：8H:4N:1L，空 class 跳过；waker 使用 effective priority。
- Robot safety语义：fresh hazard 使用 GPU result；stale/deadline 丢弃 GPU result，走 watchdog conservative stop；测试不控制 actuator。
- PTX ownership：obstacle 与 trace symbols 属于 IO module；入口必须显式路由，不能依赖 `KERNEL=KERNEL_COMPUTE` alias。
- VectorWare 定位：主要价值是 portable/brownfield control-plane development；transparent portable SIMD/data plane 仍缺失。

## 5. Unresolved

### P0 correctness/evidence blockers

1. RawWaker 无 task-slot generation；stale waker 可能命中复用后的 occupant。
2. Canonical trace harness 的 compute→IO route 与 ignored load error；原路径在 SIGSEGV 前未出现 kernel launch evidence，另需审计 timeout/listener buffer lifetime。正确 IO 路由的独立 ignored E2E 已 PASS，因此这一项是 harness closure，不是 ABI 状态 UNKNOWN。
3. Typed join 尚需完整 build/compile-fail/runtime/cancel/drop evidence；其未覆盖 raw Future/channel/lock。

### P1 semantic gaps

4. Effective-priority change不会迁移已经 QUEUED 的 task。
5. 只有单-warp pure-Low stress；multi-warp weighted fairness、starvation 与 shutdown race 未验证。
6. 没有 bounded poll/yield contract，亦没有超量 poll 的 telemetry/enforcement。
7. Host worker 已进入阻塞 syscall 后不可抢占；High 只能避免 queued inversion。

### P2 research gaps

8. PriML partial/dynamic/first-class priorities、priority polymorphism、CV ownership/promotion 与 mutex ceiling 尚未迁移。
9. PriML work/span/response/fairness cost model没有 GPU-specific theorem；SIMT/barrier/residency/hostcall 必须进入假设。
10. transparent portable SIMD lowering、uniform/varying typing 与 convergence proof 仍是 VectorWare 独立缺口。

## 10. Priority gates and scheduling impact

| Gate | Priority | Blocks | Required evidence |
|---|---|---|---|
| G0 state hygiene | immediate/orchestrator | reliable task selection | Archive done current tasks/features; reset stale current task before adding new items. |
| G1 canonical hostcall route/lifetime | **P0** | release harness reliability and canonical CPU↔GPU evidence | Preserve the already-passing independent IO 32/32 gate; fix `ONLY_TEST=trace` to surface load errors, start listener after load and exit without SIGSEGV. |
| G2 typed wait closure | **P0** | “static priority inversion prevention” claim | Compile matrix + GPU join/cancel/shutdown E2E; explicit raw API limitation. |
| G3 RawWaker generation | **P0 correctness** | safe slot reuse and typed runtime closure | Stale generation negative test, queue-wrap model, GPU reuse stress. |
| G4 reserved hostcall E2E | **P1** | admission guarantee across host service boundary | Saturate General, High uses reserve, metadata round-trip, legacy unaffected. |
| G5 queued relocation/inheritance | **P1** | dynamic effective-priority/PriML inheritance wording | Exactly-once relocation or explicit deferred semantics; no queue duplication. |
| G6 GPU fairness model | **P1** | bounded service/progress wording beyond single warp | Model + multi-warp adversarial GPU evidence. |
| G7 bounded poll/system WCET | **claim gate** | every hard-real-time/deadline claim | Until separately proved, docs/tests must continue saying cooperative, not hard real time. |
| G8 portable SIMD | **separate P3 VectorWare gap** | “complete VectorWare implementation” claim | Uniform/varying types, portable-SIMD lowering and differential GPU evidence; not a dependency for this story's control-plane completion. |

Recommended selection order: `priority-hostcall-e2e.1` and `typed-priority.1` can proceed in parallel; `priority-handle-safety.1` is the next correctness design. Do not start multi-warp performance work before G1–G3 close.

## 11. PriML → Rust/GPU transfer boundary

| PriML concept | Current mapping | Verdict |
|---|---|---|
| task/thread priority | `Priority` + base/effective slot fields | Strictly usable for fixed 3-level order. |
| high may not join lower | `PriorityToken::wait_for` + `MayWaitFor` | Exact minimal rule in progress; opt-in typed path only. |
| future handle | `TypedJoinHandle` + `CompletionCell` | Good mapping if GPU lifetime/cancel tests pass; raw TaskId is not capability. |
| priority polymorphism/partial order | sealed Low/Normal/High markers | Not implemented; do not claim. |
| dynamic/first-class priority refinements | runtime effective priority only | Not implemented as a static refinement system. |
| CV ownership/promote | none for raw GPU synchronization | Not implemented; GPU residency/barrier semantics require redesign. |
| mutex priority ceiling/inheritance | effective priority field, no queued relocation | Insufficient for strict inheritance. |
| fairly-prompt cost/fairness theorem | 8H:4N:1L + one-warp stress | Empirical analogue only, not theorem. |
| response-time bound | diagnostic `%globaltimer` | Invalid without bounded polls and GPU/platform assumptions. |

The 2019 PriML fairness paper's robot path-planning example is directly relevant as motivation: high-priority sensor/motor interaction coexists with lower-priority parallel planners. It is **not** GPU proof. The obstacle negative test supplies the missing local counterexample: priority cannot interrupt a currently running cooperative poll.
